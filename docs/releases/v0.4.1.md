# v0.4.1: fixes from the v0.3.0 hand check

A patch release with three interface and session fixes found while checking earlier releases by hand. There are no new features.

## Fixed

- **Scene Controls offer only the measurements a grid type has.** A square grid offers Chebyshev, Alternating, Euclidean and Manhattan; a hex grid offers Manhattan and Euclidean. Switching between square and hex picks the new type's first measurement and keeps the scale.
- **A name in the party list is no longer broken mid-word.** The colour dot sits beside the name instead of sharing its line.
- **A server restart keeps a running session.** Players still see the open scene after the restart. If no GM returns within five minutes, the session ends. A session the GM ended stays ended.

## Upgrading from v0.4.0

**Stop the server and back up the complete data directory before replacing the executable.** Keep `assets/` and any hidden or SQLite companion files in that backup.

The first start upgrades the database layout to save running sessions, and keeps `owlbear.db.before-upgrade` beside `owlbear.db`. Rooms, scenes and items are unchanged.

**There is no database downgrade. v0.4.0 refuses the upgraded database.** To return to v0.4.0, stop the server, keep the current directory aside and restore the complete pre-upgrade backup before starting the old executable. If restoring only the automatic copy, remove `owlbear.db-wal` and `owlbear.db-shm` from the destination before startup.

See the [hosting guide](https://github.com/spitefulFr0g/owlbear-rodeo-bun/blob/v0.4.1/docs/hosting.md#back-up-and-restore) for backup and restore details.

## Downloads

- Linux x64: `owlbear-rodeo-linux-x64`
- Windows x64: `owlbear-rodeo-windows-x64.exe`

Each executable includes the frontend and server. The release workflow checks startup, persistence and upgrading from v0.4.0 on both operating systems before publication.
