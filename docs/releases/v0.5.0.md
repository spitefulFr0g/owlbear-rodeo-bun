# v0.5.0: libraries and dock

Images now belong to a room library or an account library. The bundled server set remains read-only. A dock down the right side of a room holds assets and, for the GM, scenes. The floating Asset Manager organises assets and folders, edits names, types and defaults, and moves assets between room and account libraries.

- Drop image files onto the canvas, choose one asset type and place them together. Create a scene empty, from a library Map or from a fresh upload, with alignment in the importer.
- Players see their own uploads and the server set. Trusted players have the same library view and can upload with the uploads switch off. Cast displays have no library interface.
- Administrators set room and account quotas; GMs set the player quota. Originals and derived files count, including uploads in progress. Deleting a library asset frees quota immediately while placed images keep working.
- The old pickers, separate image edit dialogs, Scenes dialog, manual tile arrangement, Import / Export dialog and `.owlbear` file route are replaced.

## Upgrading from v0.4.1

**Stop the server and back up the complete data directory before replacing the executable.** Include `assets/` and any hidden or SQLite companion files.

The first start upgrades the database to layout 4 and keeps `owlbear.db.before-upgrade` beside `owlbear.db`. Existing rooms, scenes and placed images keep working. Room and account libraries start empty; the upgrade does not reconstruct library entries from placed images.

**At that first start, stored files that no room places and no library holds are cleared, along with incomplete uploads.** The automatic database copy does not back up those image files. Keep the complete pre-upgrade data-directory backup.

**There is no database downgrade.** To go back to v0.4.1, stop the server, keep the current data directory aside and restore the complete pre-upgrade backup before starting the old executable. Restoring only the database copy cannot recover cleared files. When restoring a database copy, remove stale `owlbear.db-wal` and `owlbear.db-shm` files from the destination before startup. See the [hosting guide](../hosting.md#back-up-and-restore).

## Bring over each browser library

Each GM should open a room they run, open the Asset Manager and run the browser library import **in the browser and at the original server address that hold their old library**. A library at another address or in another browser requires opening v0.5.0 there once. Any account can create a room to run the import.

The import reads all uploaded maps and tokens into the GM's account library, retaining names, folders, token defaults and saved map grids. It skips built-ins and originals already imported, reports unreadable or oversized images, and stops at the account quota while keeping completed imports. The browser library is left untouched, as are the browser id, nickname and settings. There is no `.owlbear` file import or export.

Players' old uploads do not become library entries. Their placed images still work; My uploads starts empty until they upload again.
