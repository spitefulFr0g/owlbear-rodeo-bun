# v0.4.0: scenes and live play

Prepare multiple scenes in a room and share token movement, rulers and pointers live with everyone viewing the same scene.

## What's changed

- Create, name, edit, duplicate and delete scenes in the Scenes dialog. Start with an empty scene or import a map with alignment and Fog Fill settings.
- Prepare another scene as the GM without moving players. **Show to players** switches the open scene; **Bring players here** moves their view once. The cast display stays on the open scene while the GM prepares elsewhere.
- Use Scene Controls for grid appearance, Fog Fill, view-only scenes and movement mode. Assign a scene as the welcome screen outside a session.
- See token moves, resizes and rotations while they happen. Hidden items follow the same visibility rules as committed changes, and live activity stays within the scene being viewed.
- Share rulers and pointers live. Movement mode is on by default and shows a token's distance while it is dragged, using the scene's square or hex grid rules.
- See a mark when a GM is viewing another scene, without exposing private scene names to players. Shared dice rolls and timers still reach everyone in the room.

Live activity is never saved or added to undo. Concurrent drags do not lock an item: each person controls their own held drag, and the last release to reach the server determines the saved position. Drawings, fog shapes and new items still appear when finished.

## Upgrading from v0.3.0

**Stop the server and back up the complete data directory before replacing the executable.** Keep `assets/` and any hidden or SQLite companion files in that backup.

The first start upgrades the database automatically and keeps `owlbear.db.before-upgrade` beside `owlbear.db`. Existing rooms keep their scene and items. Movement mode is on for existing scenes as well as new scenes.

**There is no database downgrade. v0.3.0 refuses the upgraded database.** To return to v0.3.0, stop the server, keep the current directory aside and restore the complete pre-upgrade backup before starting the old executable. The automatic pre-upgrade copy contains the database only, not `assets/`; it is replaced by the next database upgrade. If restoring only that copy, remove `owlbear.db-wal` and `owlbear.db-shm` from the destination before startup. Images changed or removed since the upgrade may require the complete backup.

See the [hosting guide](https://github.com/spitefulFr0g/owlbear-rodeo-bun/blob/v0.4.0/docs/hosting.md#back-up-and-restore) for backup and restore details.

## Downloads

- Linux x64: `owlbear-rodeo-linux-x64`
- Windows x64: `owlbear-rodeo-windows-x64.exe`

Each executable includes the frontend and server. The release workflow checks startup, persistence and upgrading from v0.3.0 on both operating systems before publication.
